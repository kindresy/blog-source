## 结论

**PASS（限定当前寄存器供数接口：额外Payload 0～4字节，以及5字节提交前拒绝）。** 不能将此标记扩展为完整IBI协议长度协商验收。

0、1、2、3、4字节均实际发送并由Host比较正确；5字节返回-90/EMSGSIZE，不截断为4字节，不消费新的软件sequence，原完成结果保留，Target维持IDLE。Host超限前后received=3、stored=3，invalid/dropped均0；随后2、3字节继续成功，证明本次拒绝未破坏后续合法发送。

“没有新增Host接收”是日志实测；“校验先于MMIO、不会发布SIR”是源码和模型测试证据。本轮没有抓波或MMIO总线跟踪，不能将二者写成外部波形实测。

## 命令作用与实现

本阶段前提：016中的枚举、on/active、IBIRULES=4和ENEC已完成；Target已结束上一笔、全局IDLE、DA有效。所有Target命令在EMU CLI执行。Host命令以板端根目录为工作目录，设置 `dut=sys/bus/i3c/devices/0-<TARGET_PID>`。设置变量仅为shell操作，不触发总线。

| 命令/执行端 | 参数与内部实现 | 总线行为与判据 |
| --- | --- | --- |
| Target `i3c_test ibi caps` | get_caps报告max_payload4、max_wire_bytes5、SIR许可及pending；只读现场 | 不产生新事务；不能以静态caps替代实际发送验证 |
| Target `i3c_test ibi send A5 <payload> 5000` | MDB两位hex；Payload连续hex，-表示0；超时是Target tick毫秒。CLI解析后submit首先检查长度，合法时才校验会话、acquire、写94和8c、置SIR | 合法长度触发IBI：START/仲裁44/R、Host ACK、MDB和Payload、读数据T-bit/结束握手、STOP；Host自动接收 |
| Target `i3c_test ibi send A5 1122334455 5000` | 5字节超限；submit在MMIO之前返回EMSGSIZE，不写供数或请求、不截断、不覆盖前一结果 | 设计上无IBI；实测CLI -90、Host计数不变，未抓波 |
| Target `i3c_test ibi poll` | 仅合法发布后需要；检查当前SIR完成和响应剩余长度，安全释放所有权 | 不重新发送；PENDING仅重复poll，不重复send；超限后无需poll新请求 |
| Target `i3c_test ibi status` | result读取缓存 | 无总线；超限后必须仍为上一笔seq3/length4/DONE |
| Target `i3c_test status` | 查询全局硬件和软件会话状态 | 不主动发送；超限后IDLE、DA有效、last_error/cleanup_error为0 |
| Host `cat "$dut/ibi_result"` | 读取回调缓存计数和数据，不取硬件FIFO | 无总线；超限前后计数相同且无新增记录；合法发送新增长度=Payload+1 |

合法发送使用普通SLV_SIR_DATA寄存器，不是往Target TX FIFO推送。SLV_INTR_REQ长度[23:16]不含MDB，使用32位MMIO；Host接收通过RX FIFO、IBI槽和回调缓存完成。不能把Host length与Target payload_len直接比较而漏算MDB。

## 实际步骤与结果

每个合法命令后执行poll、IBI status和全局status，再由Host读取结果；没有并发在途请求。

| 顺序 | Target send参数 | Target证据 | Host新增记录/计数 | 判定 |

| 1 | A5 - 5000 | 用户仅确认phase=DONE | seq1 length1 a5 | 接收基线通过 |
| 2 | A5 11 5000 | 完整DONE/ret0/remaining0 | seq2 length2 a511 | 通过 |
| 3 | A5 11223344 5000 | 完整DONE/ret0/remaining0，回到IDLE | seq3 length5 a511223344；计数3 | 最大合法长度通过 |
