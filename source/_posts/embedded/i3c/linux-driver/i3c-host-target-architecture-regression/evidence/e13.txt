# I3C 双向 PIO 工作带宽与软件负载对照实验报告

归档日期：2026-11-03。实验日期、操作者及板卡编号未提供。本文记录用户回传的 FPGA 结果摘要，不宣称本次由助手执行了硬件回归。

## 1. 结论与验收边界

16 字节、50 个计量包、每组另有 1 个预热包，Write/Read 分别比较 WORK=0、1、15。数据调用吞吐约 10.2 kB/s，P95 约 1.58–1.59 ms；WORK 从 0 增至 15 时，含握手吞吐下降约 25%，两个方向每包端到端耗时均增加约 2.66 ms，符合负载位于数据完成后、DONE 通知前的设计。

## 3. 测量口径与结果

Host 使用 CLOCK_MONOTONIC。`transfer_ns` 为已确认成功的计量包数据调用耗时之和；`wall_ns` 从预热结束的 NEXT 控制写之后，到最后计量包 DONE 被接收为止。后者包含逐包准备、IBI、计量包之间的控制交接、软件处理和调度，排除初始枚举、START、预热以及最终 FINISH/FINAL 与 release。最终交接失败仍使结果无效。

计量有效载荷为 16×50=800 字节，预热不计入速率。数据吞吐=800/transfer_seconds；含握手吞吐=800/wall_seconds。P95 为已确认计量包调用耗时排序后的 ceil(0.95×50)=第48项，不是端到端 P95。表内平均时间由截图吞吐反算，存在四舍五入误差。

## 4. 理论对照与解释

按截图采用的简化模型，100 kHz 每周期 10 μs，SDR 每字节按 8 位数据加 1 个协议位计，数据段上限约为 100000/9=11111 B/s。16 字节数据段约 1.44 ms。该模型忽略寻址、起止条件及软件开销，不能直接充当整个事务的精确理论值。

实测摘要中的数据调用约 1.57 ms，约为上述数据段上限的 91%–92%，数量级合理。额外约 0.13 ms 不能仅归因于某一个寄存器或总线阶段。截图还称 WORK=1 的长度扫描每增加 1 字节增加约 90.4–90.9 μs；此项只有文字摘要，没有逐长度结果，作为用户观察保留，不作为本报告独立拟合结论。

含握手吞吐约 1.5–2.1 kB/s，是逐包 IBI 流控的有效工作吞吐。每包均经历 READY、数据调用、Target 校验/工作负载、DONE、NEXT；不是连续占满总线。WORK 的额外延迟也包含调度与交接影响，不能全部当作纯 CRC 运算耗时。软件计时不能证明实际 SCL 恰为 100 kHz。

## 5. 命令作用与实现

| 执行端与命令 | 前提、参数与目的 | 内部动作、线上行为与完成条件 |
| --- | --- | --- |
| Target：`i3c_test bandwidth run write 16 50 W` | 已枚举、IDLE、队列可用；16=字节，50=计量包，W=0/1/15 | CLI→bandwidth run→控制接收及逐包状态机；READY 日志表示等待 Host START，不是测试通过。Write 接收 FIFO/response 并检查期望内容；完成后执行 WORK 再发 DONE IBI |
| Target：同上改 `read` | 参数须与 Host 一致 | 逐包准备期望 TX 数据和发送队列，等待 Host Private Read 完成，再执行 WORK 和 DONE；由 Host 比较完整16字节 |
| Host：`./i3c-host -d "$NODE" auto bandwidth "$GEN" DIR 16 50 60000 W` | Target READY，NODE 为当前字符设备，GEN 为实际代次；60000 为事件等待超时毫秒 | CLI→bandwidth_load→claim/prepare events→START→READY/数据 ioctl/DONE→NEXT 或 FINISH→FINAL→release。读写使用已有 PIO 驱动路径，无 DMA；失败不自动重跑 |
| Host：`uname -a`、`sha256sum ./i3c-host` | 部署包目录 | 只读系统与文件，不触发 I3C 总线事务；用于版本归档 |

控制 START/NEXT/FINISH 本身通过 Private Write 发送，有控制 CRC；START opcode 携带方向与 WORK。软件 START 控制帧不是物理 START 条件的同义词。数据由 run/generation/sequence/direction 确定，Write 在 Target 检查，Read 在 Host 检查；控制与通知同时校验顺序和会话。

协议预期：Private 数据事务包含 START、动态地址及 R/W、地址 ACK/NACK、数据及 SDR 协议位、结束条件；Write 的第9位按写方向规则处理，不能逐字节笼统描述成 ACK；Read 的 T-bit/终止由读方向规则处理。READY/DONE 为 Target 发起、Host 接收的 IBI；控制写还产生额外总线事务。是否含额外广播头、Repeated START 以及实际 STOP 边界需以当前驱动和抓波确认，本轮没有抓波，不将预期描述为实测。

WORK 每轮执行64字节 CRC/内存更新，放在数据完成之后、DONE 之前；没有额外 sleep 或逐包打印，未主动屏蔽 IRQ。这是协作式处理负载，不是 CPU 利用率百分比，也不等同于并发生产业务。完整成功时 calls=(50+1)×WORK，分别应为0、51、765；这些是验收期望，并非截图已测字段。

正常完成须 Host HOST_PASS、timing_valid=1、ret=cleanup=0、completed=50，与 Target LOCAL_PASS、completed=50 参数相符。READY/等待通知仅为 pending。超时或校验失败停止该组，Host 尝试 release；不得认为失败自动保留了全部 FIFO 现场，需保存错误及 cleanup 日志，禁止无记录重跑。
