## 1. 软件配置流程：配置什么、为什么配置

### 1.1 两端分工

```text
i.MX93 Linux                         EMU / Target
board-modules-load                  i3c_test run case_004
  i3c.ko：I3C core                    CLI / Target 会话管理
```

### 1.3 CTRL0、CTRL1 和 DEVICE_CTRL 的含义

| CTRL0 字段 | 位 | 值 | 含义 |
|---|---|---:|---|
| PENDING_INT | [19:16] | 0 | 配置值清零；不能当作通用 W1C 清中断动作解释 |
| SLV_CLK_DATA_TURN_TIME | [14:12] | 2 | GETMXDS 相关的时钟到数据转换时间能力编码；不是 2 µs，也不是 Host 的 SDA hold 寄存器 |
| SLV_MAX_WR_SPEED | [10:8] | 0 | 最大写速率能力编码，不是把 SCL 设为 0 Hz |
| SLV_MAX_RD_SPEED | [6:4] | 0 | 最大读速率能力编码 |
| SLV_STOP_PERMIT_BW_WR | [2] | 0 | 写转读之间允许 STOP 的能力声明；不是禁用 STOP 检测 |
| SLV_DEF_BYTE_SUPPORT | [1] | 1 | Defining Byte 支持能力声明 |
| MODE_I2C | [0] | 0 | 不强制固定为 I2C，允许按 I3C 流程取得动态地址 |

CTRL0 对其余位做保留式读改写；`0x2002` 是被配置字段的结果，完整寄存器只有在其他位为零时才等于 `0x00002002`。截图中 `[14:16]` 已按用户确认修正为 `[14:12]`，mask 为 `0x7000`。这些能力输入与 GETMXDS 的关系见 DWC databook §4.2.4.3；是否经相应响应暴露还受综合配置和 BCR 能力位影响。

CTRL1 的 `[31:16]=0xBEEE`、`[15:8]=0`、bit7=1、`[6:0]=0x44`。wrapper 的静态地址使能是 **bit7**，而 IP DEVICE_ADDR 的静态地址使能是 **bit15**，二者不应混淆。

DEVICE_CTRL bit27 的含义是自适应 I2C/I3C 行为：配合 `mode_i2c=0`，在识别总线类型之前约束自动 Hot-Join，并按手册规定处理首次 `0x7E/W` 与 glitch-filter 控制；取得有效动态地址后进入相应 I3C 工作状态。它既不是静态地址使能，也不是 SDA 推挽使能的直接开关。依据为 DWC databook §4.2.1，印刷页 178。

本例不通过 Target 软件逐位切换 OD / 高阻 / PP；协议阶段中的接收、ACK 和 SDA 驱动切换由 IP 完成。
